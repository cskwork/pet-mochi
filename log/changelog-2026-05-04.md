# Changelog — 2026-05-04

## Decisions captured in PRD

### 1. Behavior choreography (REQ-094…099, new §9.11)

**What:** When the LLM is consulted at high-salience moments, it returns a
`{preset, variant, bubble}` triple — a key into a closed catalog of
choreographies — instead of free text. Each preset is an ordered
`AnimationStep[]` over the existing `MovementState` enum. Bubble tokens are
restricted to a closed vocabulary (glyphs + pet-language sounds).

**Why:** User wants Mochi to feel lively without seeming human-like. The
existing `applyAction` path already returns `AnimationStep[]`, so the data
model is reused — the LLM just becomes a chooser. Free-form sentences would
have undermined the "not-a-chatbot" positioning.

**Alternatives considered:**
- Closed pet-language vocabulary only (no animation choreography). Rejected
  because the user wanted *more* expressiveness, not just non-verbal.
- Third-person status captions (`Mochi is thinking about rain`). Rejected as
  it broke the "pet, not narrator" framing.

### 2. Idle-triggered 12h status report (REQ-070…076, redefining §9.8)

**What:** Replaces the fixed daily-cadence "Daily Reflection". Fires when
(now − lastReportAt ≥ 12h) AND (pet has been in `idle`/`sleep` movement state
for ≥60s with no in-flight action). Missed windows are dropped; no catch-up.
Input to the LLM is a *summary statistics payload* over the 12h window — never
raw events. Output is `{learned, noticed, wants}` plus 200–400 char prose.

**Why:** Fixed daily cadence assumed the host was always on; the user pointed
out laptops sleep, are turned off, etc. Idle-trigger respects compute and
preserves the "pet feels alive offline" north star. Summary statistics keep
the prompt small (compute budget) and reduce LLM hallucination surface.

**Alternatives considered:**
- (a) Replace daily reflection entirely with 12h idle model — chosen.
  `dreams/` directory and existing schema reuse keeps changes surgical.
- (b) Coexist: dreams = short poetic line, reports = analytic. Rejected as
  duplicate scaffolding for marginal benefit.
- (c) Daily reflection with 12h supplementary report. Rejected as cadence
  noise.

### 3. Expressive sprite set (REQ-015)

**What:** 8 new `MovementState` values backed by hand-drawn sprites:
`stretch`, `peek`, `tilt_head`, `shake`, `nuzzle`, `wiggle`, `dizzy`,
`surprise`. Generated via Codex CLI image-gen against the existing 14-sprite
reference set to preserve line weight, palette, and scale.

**Why:** A richer choreography catalog needs more pose primitives. Eight
chosen as the floor of "noticeably more expressive" without doubling the
sprite-maintenance burden. Excluded from the original shortlist: `bonk`
(too cyber for Mochi's tone), `purr` (visually overlaps with `nuzzle`).

## Implementation work (Phase A + Phase B)

Plan was generated by the Plan subagent (13 steps, 4 phases). Phase A
(sprites + enum) and Phase B (backend rewrite) executed in parallel.

### Phase A — sprites + enum

- Codex CLI image_gen produced 8 PNGs in one batch session
  (mochi-stretch / peek / tilt-head / shake / nuzzle / wiggle / dizzy /
  surprise), 1024x1024, ~1MB each, anchored against `mochi-idle.png`.
- `MovementState` union extended from 14 → 22 literals.
- `MochiSprite.svelte` `SRC` record extended exhaustively — TypeScript
  exhaustiveness on `Record<MovementState, FrameSrc>` enforces parity.

### Phase B — backend status report rewrite

- `pet_state.last_report_at TEXT` added to `SCHEMA_SQL` for fresh DBs;
  legacy DBs upgraded by `ensure_pet_state_has_last_report_at` (PRAGMA-guarded,
  idempotent ALTER). `daily_reflections` table left intact for compat.
- New `status_reports (id, window_start, window_end, learned, noticed,
  wants, prose, file_path, created_at)` table + index.
- New `models::StatusReport` / `models::NewStatusReport` + camelCase serde.
- New `db::save_status_report` / `list_status_reports` / `last_status_report`
  / `events_between` (so the 12h window can be reconstructed).
- `llm::report::WindowSummary` + `summarize_window` aggregator (event
  counts, salience sum, mood distribution, interaction rate, top-3
  memories) — never sees raw user-typed text.
- `llm::report::deterministic_status_report` — REQ-076 fallback. Produces
  a `ValidatedStatusReport` (passes 180-440 char prose validation) from
  stats alone, so cadence survives an LLM outage.
- `llm::prompts::status_report_prompt` + `validate_status_report_json`
  (strict serde + length window + fenced-JSON recovery) +
  `StatusReportValidation` enum.
- `commands::run_status_report` Tauri command — load pet → compute window
  → `summarize_window` → LLM (60s cooldown key `llm_status_report`) or
  fallback → write `dreams/YYYY-MM-DD-HHMM.md` → save row → stamp
  `last_report_at` → log `STATUS_REPORT_DUE` event.
- `commands::list_status_reports` Tauri command for the Settings UI.
- `lib.rs` invoke_handler registers both new commands.
- `salience.ts`: `DAILY_REFLECTION_DUE` → `STATUS_REPORT_DUE` (PRD §14).
- `state.ts`: `lastReportAt: string | null` added to `PetState` +
  `newPetState` initialization.
- `statusReportGate.ts` (new) — pure-function `shouldFireStatusReport` for
  REQ-070..074: 12h elapsed AND idle/sleep AND ≥60s dwell AND not in-flight,
  with no-catch-up semantics enforced through `lastReportAt` stamping.
- `bridge/api.ts`: typed `runStatusReport()` / `listStatusReports()` +
  `StatusReport` type.

## Phase C — behavior choreography (REQ-094..099)

### Frontend (TypeScript)

- `src/lib/sim/choreography.ts` (new):
  - `ChoreographyKey` union (8 closed presets: `greet_returning`,
    `confused_hesitate`, `delight_burst`, `curious_peek`, `sleepy_settle`,
    `playful_wiggle`, `dizzy_recover`, `gentle_nuzzle`).
  - `ClosedToken` union (10 glyphs/sounds: `…`, `?`, `♡`, `!`, `nyu`,
    `boop`, `mhmm`, `hmf`, `ah`, `oh`).
  - `CHOREOGRAPHY_CATALOG` — 8 presets × 1-3 variants each, every step
    typed as `AnimationStep` over `MovementState`.
  - `validateChoreographyPayload(raw)` — strict type narrowing; rejects
    unknown preset, out-of-range variant, free-text bubble, malformed
    shapes. Returns `null` on rejection (frontend then runs fallback).
  - `pickFallbackPreset(state, event)` — REQ-098. Mood × event-type matrix
    yields a deterministic preset; variant index seeded from a string
    hash of `(preset|event|mood|relationshipLevel)` so the same situation
    always plays the same beat without canned-feeling repetition across
    different situations.
- `Pet.svelte`:
  - New `maybeChoreography(event)` — uses `tryEnterAutonomous` with
    `kind: "choreo"` and a 30s local cooldown; tries
    `api.chooseChoreography(eventType)`, validates the reply, falls back
    to `pickFallbackPreset` on any failure (REQ-098), plays steps via
    existing `playSteps`, surfaces the closed-token bubble through the
    same `flashBubble` pipe.
  - `eventBus.subscribe` now branches: `USER_RETURNED` ≥ 30min still goes
    through chat (`maybeAutonomousSpeak`); other events that pass
    `shouldCallLLM` go through `maybeChoreography`. The shared
    `autonomousInFlight` flag prevents both from firing concurrently.
- `bridge/api.ts`: `chooseChoreography(eventType)` typed Tauri invoke
  returning `{preset, variant, bubble?}`.

### Backend (Rust)

- `llm/prompts.rs`:
  - `CHOREOGRAPHY_PRESET_KEYS` and `CLOSED_BUBBLE_TOKENS` constants —
    must stay in lockstep with the frontend catalog.
  - `choreography_prompt(pet, event_type)` — renders the closed key list
    and bubble vocabulary inline so the LLM cannot invent options.
  - `validate_choreography_json` + `ValidatedChoreography` (camelCase
    serde) + `ChoreographyValidation::Reject(reason)` enum.
  - `sanitize_for_prompt` extended with `</state>` and `</event>` so
    prompt-tag injection through event names is blocked.
- `commands::choose_choreography` Tauri command. Acquires the canonical
  `llm_autonomous` 90s cooldown (REQ-097), calls the provider with
  `max_tokens=80, temperature=0.3`, validates the JSON, returns
  `Err` on any failure so the frontend can fall back deterministically.
- `lib.rs` `invoke_handler` registers the new command.

## Notes for future cleanup

- The new sprites are 1024x1024 (Codex's smallest supported size). At
  display time they're rendered at ~140px so file size is fine, but a
  build-time downscale step could trim disk usage to <200KB each.
- `daily_reflections` SQLite table + `run_daily_reflection` command are
  retained for backwards compatibility but no longer surfaced in the UI.
  Safe to remove in a future migration if no external integrations call
  the old command.
